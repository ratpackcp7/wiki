# Ladybird adopts Rust, with help from AI

Simon Willison highlights a significant case study by **Andreas Kling** regarding the **Ladybird browser project's** transition from C++ to Rust. This move represents a sophisticated application of AI coding agents for high-stakes, large-scale architectural changes.

## 1. Strategic Shift: From Swift to Rust
Originally, the Ladybird team hoped to use **Swift** as their memory-safe language of choice. However, they pivoted to **Rust** after concluding that Swift's platform support outside the Apple ecosystem had not matured sufficiently for their needs.

## 2. The Porting Process: LibJS
The team began the transition with **LibJS**, Ladybird's JavaScript engine. This component was chosen because its core elements—the lexer, parser, AST, and bytecode generator—are self-contained and highly testable.

### Key Metrics & Tools
*   **Tools Used:** Claude Code and OpenAI Codex.
*   **Scale:** Approximately **25,000 lines of Rust** code.
*   **Timeline:** Completed in **two weeks** (estimated to take months if done manually).
*   **Methodology:** "Human-directed, not autonomous." Kling steered the agents through hundreds of small prompts to define the architecture and order of operations.

## 3. Verification and Quality Control
The success of the port relied on rigorous validation against existing infrastructure:
*   **Test Suite:** Utilized the extensive [test262](https://github.com/tc39/test262) conformance suite.
*   **Parity Requirement:** The team mandated byte-for-byte identical output between the old C++ pipeline and the new Rust pipeline.

> "We've verified that every AST produced by the Rust parser is identical to the C++ one, and all bytecode generated by the Rust compiler is identical to the C++ compiler's output. Zero regressions across the board." — *Andreas Kling*

## 4. Analyst Insights
Simon Willison identifies two "huge unlocks" that made this agentic engineering successful:
1.  **High-Quality Conformance Suites:** Having a robust test suite like `test262` allows for immediate validation of AI-generated code.
2.  **Differential Testing:** The ability to compare AI output against a "trusted" existing implementation (the original C++ code) makes using coding agents a much safer bet for critical infrastructure.
